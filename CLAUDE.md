# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## О проекте

`products-store` (`hexlet_qa_market`) — учебный интернет-магазин от Hexlet, предназначенный для тренировки QA-инженеров. В приложение **намеренно заложены баги**, которые студенты должны находить. Прежде чем «чинить» странное поведение, проверь, не является ли оно преднамеренным (см. раздел «Намеренные баги»).

Детали по слоям лежат рядом с кодом: `server/CLAUDE.md` (бэкенд) и `src/CLAUDE.md` (фронтенд) — они подгружаются при работе с соответствующими каталогами.

## Команды

Все команды запускаются из каталога `products-store/`; список целей — в `Makefile` (тонкая обёртка над npm-скриптами).

Отдельный тест: `npx vitest run <файл>` или `npx vitest run -t '<имя теста>'`.

Типы не проверяются автоматически: отдельного шага typecheck нет ни в CI, ни в сборке Vite — только редактор или `npx tsc --noEmit` вручную. CI гоняет `npm ci && npm run lint && npm test && npm run build`.

## Архитектура

### Два процесса в dev, один в проде

- **dev**: Vite отдаёт SPA на `:8080` и проксирует `/api` на Fastify (`:3001`, запускается через `fastify-cli`, точка входа `server/app.js`).
- **прод**: единственный процесс Fastify (`npm run start:prod`) отдаёт собранный `dist/`, картинки товаров и `/api`. Переключение делает плагин `server/plugins/static.js`: если `dist/` не существует — плагин no-op (dev), если существует — регистрируется `@fastify/static` + history-fallback на `index.html` для клиентских маршрутов.
- Фронт всегда ходит на `API_BASE` из `src/services/apiConfig.ts` — по умолчанию same-origin `/api`, переопределяется через `VITE_API_URL`.

### Контракт API

`/api/products` намеренно повторяет формат ответа DummyJSON (`{ products, total, skip, limit }`, `limit=0` = «без лимита») — фронтовые типы (`src/types/dummyStoreResponse.ts`) завязаны на эту форму. Меняешь формат на сервере — правь типы и саги на фронте.

## Намеренные баги

`POST /api/orders` (`server/routes/api/orders.js`) **всегда** отвечает 500, при этом фронт в `Cart.tsx` открывает модалку «заказ оформлен» независимо от результата запроса. Это учебный баг, а не дефект — на него есть тест `server/test/orders.test.js`, который проверяет именно 500.

## Конвенции

oxlint (`.oxlintrc.json`) линтит, oxfmt форматирует; что он не трогает, перечислено в `.oxfmtignore`. Перед коммитом — `make lint-fix`.

## CI/CD

В репозитории живут две версии магазина с разными наборами багов: ветка `main` собирается в образ с тегом `v1`, ветка `v2_bug_fixes` — в `v2`. Учитывай, в какой ветке работаешь.
